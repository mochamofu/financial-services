# ToriiGate プロダクト・ロードマップ（MVP → 販売可能な製品）

「動くMVP」を「商売として売れる製品レベル」に引き上げるための、正直なギャップ分析と
優先順位。現状 → 次の投資(本番運用基盤) → その先、の順。

## 現在地（このリポジトリ）

- ✅ 多層検知エンジン（トラップ/署名/なりすまし/挙動）＋段階的アクション
- ✅ 2つの導入形態（ASGI / リバースプロキシ）、CDN移行不要
- ✅ Web Bot Auth（RFC 9421 / Ed25519）署名検証
- ✅ ポリシー（YAML/JSON）、robots.txt生成、可視化ダッシュボード
- ✅ レッドチーム評価＋独立コード監査 → Critical含む多数を修正済み（[security-assessment](./security-assessment.md)）
- ✅ **本番運用基盤**（今回追加）：Prometheusメトリクス・構造化ログ・ヘルスチェック・
  Redis共有状態による水平スケール・脅威フィード自動更新・Docker/compose

## 製品レベルへの残ギャップと優先順位

### P0 — 本番運用基盤（今回のPRで着手）
| 項目 | 状態 |
|---|---|
| メトリクス（Prometheus）/ヘルスチェック | ✅ 実装 |
| 構造化ログ（JSON） | ✅ 実装 |
| 水平スケール（共有状態 Redis） | ✅ 実装（`StateStore`） |
| 脅威フィード自動更新（F-1対応） | ✅ 実装（`threatfeed`） |
| Docker / docker-compose | ✅ 実装 |
| 負荷試験・レイテンシSLOの実測 | ⬜ 未（次段） |
| Helm chart / k8s マニフェスト | ⬜ 未 |

### P1 — SaaS コントロールプレーン（事業運営の骨格）
サブスク事業として各社に売るには、インストール済みゲートウェイを束ねる中央基盤が要る。
| 項目 | 内容 |
|---|---|
| マルチテナント管理 | テナント登録・APIキー・RBAC |
| 課金・従量メータリング | 解析リクエスト数の計測 → Stripe連携・プラン強制 |
| ポリシー/署名/レンジの配信 | 中央で更新 → 各ゲートウェイへpull配信（フィードを製品化） |
| 集約ダッシュボード | 複数サイト横断の可視化・アラート |
| セルフサーブ導線 | サインアップ→APIキー→設置までのオンボーディング |

### P2 — 検知の深化（差別化の核・持続的な堀）
レッドチームが示した「識別情報ベースの原理的限界」を埋める層。
| 項目 | 内容 |
|---|---|
| TLS/JA4 フィンガープリント | TLS経路上でのクライアント指紋（完全ブラウザ偽装への対抗） |
| Web Bot Auth レジストリ・サービス | 署名エージェントの鍵ディレクトリ・信頼スコアリングの運用 |
| 挙動ML | リクエストパターンの異常検知 |
| クライアントサイドJSチャレンジ | ヘッドレス検出の強化 |
| 動的トラップ | テナント毎の動的ハニーポット（V-6対応） |

### P3 — 到達チャネル（パッケージング・統合）
| 項目 | 内容 |
|---|---|
| クラウドマーケットプレイス | AWS/Azure出品（co-sell、エンタープライズ決済経路） |
| CMS/サーバ統合 | WordPressプラグイン・nginx/Caddyモジュール・Cloudflare Worker |
| SDK / API ドキュメント | 各言語クライアント・OpenAPI |

### P4 — 信頼・コンプライアンス（エンタープライズの前提）
トラフィックを見る製品ゆえ、信頼の担保が販売の前提条件になる。
| 項目 | 内容 |
|---|---|
| データ取扱い・プライバシー | 何を保存し何を保存しないかの明文化、Trustページ |
| SOC2 / ISMS への道筋 | 監査対応、日本ではプライバシーマークも |
| SLA / サポート体制 | 稼働保証・インシデント対応 |
| AI事業者ガイドライン対応の統制レポート | 大企業調達での差別化（事業計画の3層目） |

## 推奨シーケンス

```
現在 ─▶ P0本番運用基盤(着手済) ─▶ 最初の10社を monitor→enforce で獲得
        │
        ├─▶ P1コントロールプレーン(課金・配信) … 10社の運用が回り始めたら
        ├─▶ P2検知深化(Web Bot Authレジストリ→JA4) … 差別化要求が出たら
        ├─▶ P3チャネル(Marketplace/CMS統合) … 直販の型が固まったら
        └─▶ P4信頼(SOC2等) … エンタープライズ商談が立ち上がったら
```

GTM（誰にどう売るか）は [gtm-japan.md](./gtm-japan.md) を参照。プロダクトの各段は
GTMの各フェーズ（0→1 / 1→10 / 10→100）と対応させて進める。

> 原則：**すべてを作ってから売る、のではない。** P0で「本番投入できる」状態にし、
> monitorモードで最初の顧客に実トラフィックを流させ、その学習でP1以降の優先順位を
> 決める。検知深化(P2)は顧客が「偽装スクレイパーが抜ける」と言い始めてから重くする。
